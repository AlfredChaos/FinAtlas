# Domain Model

## 1. 建模策略
FinAtlas 采用轻量 DDD。核心域集中在导入证据链、台账事实、分类学习、月报快照和 AI 可解释问答，避免在单用户 MVP 中引入过度抽象或全量事件溯源。

## 2. 子域划分
- 核心域：导入与证据、台账、分类、报表与快照
- 支撑域：账户与来源、AI 与审计
- 通用域：鉴权、对象存储接入、消息队列、缓存、日志

## 3. 核心对象关系
- `Account` 定义来源与导入配置边界
- `ImportJob` 负责一次导入全生命周期和中间产物索引
- `Transaction` 与 `InvestmentTrade` 是可查询、可统计、可下钻的事实真相
- `Category` 与 `CategoryRule` 管理消费理解与学习闭环
- `MonthlySummary` 负责固定账期的稳定报表投影
- `AgentRun` 记录 AI 对结构化数据的解释性访问

## 4. 领域不变量
- 导入与统计都必须保留证据链
- 幂等与去重优先于吞吐
- 错误禁止静默
- 报表口径必须版本化
- AI 建议不能绕过业务规则直接改账

## 5. 建模边界说明
- 不把交易与投资交易强行合并为一张超级表
- 不在 MVP 上采用事件溯源作为核心存储模式
- `ReviewCase` 在 MVP 阶段作为 Import 聚合内实体，后续复杂时再独立
